# 智能体群聊

入口位于现有「DedsiWork Ai Agent」标题旁的「智能体群聊」。功能复用当前工作空间、工作项服务、领域模型服务和研发任务的工作树、验收及合并流程。

## 项目角色

在工作空间设置中填写项目本地目录。群聊读取该目录下 `.codex/agents/*.toml` 的 `name`、`description`、`developer_instructions`、`model` 和 `model_reasoning_effort`。角色由项目配置决定，不固定为产品、前端或后端。配置必须位于当前项目内，不允许通过符号链接读取项目外的角色文件。

刷新配置会重新发现角色；已创建的群聊保留角色配置及 SHA-256 快照，防止进行中的讨论或研发因配置变化而漂移。角色文件中的 MCP、沙箱和启动脚本不直接执行，运行环境统一控制实际工具和权限。

## 讨论与确认

用户选择相关角色、提供基本信息，设置并行上限和总 token 预算。默认并行上限为 2，可设置 1–4；每次最多选择 8 个角色。

每轮由相关角色独立评审，主持人汇总为统一方案。讨论使用隔离的 Codex App Server，允许在只读沙箱中检查相关代码，禁用 MCP、应用、插件、钩子和继续委派，不执行项目或远程业务写入。提供已有工作项和领域模型的部分索引作为参考；不能核实的代码、业务事实必须明确标记。模型仍可能犯错，确认前应核对验收标准和待决事项。

完整用户输入、角色意见和方案保存在当前工作空间。角色意见限制长度；上下文超过限制时停止并提示整理需求，不静默截断用户约束。补充信息会启动新一轮评审，旧轮消耗仍计入同一预算。

确认页面展示工作项、领域模型、执行角色、文件范围、依赖和基准分支，并支持编辑完整方案 JSON 后重新预览。待决问题未解决时不能确认。每个模型沿用现有领域模型验证规则。

「确认创建并开始并行研发」在本地 DedsiWork 创建预览中的记录；不自动发布 Azure DevOps 工作项。记录写入使用现有业务服务，工作项和模型在同一 SQLite 事务中保存。确认具有幂等性；部分研发任务准备失败时，继续操作会补齐缺失的任务，不重复创建已保存记录。

## 并行研发

研发任务使用现有独立 Git worktree，每项任务保留配置角色的模型、推理强度和指令。系统校验依赖是否存在、是否形成循环，以及文件或目录范围是否重叠；共享范围必须添加显式依赖。文件范围是任务约定，不是操作系统级文件访问隔离。

独立任务在并行上限内执行。依赖任务等待前置任务通过现有验收与合并流程，且合并提交已进入选定基准分支，再从最新基准提交启动。系统不自动验收、提交或合并。单项失败后其他正在执行的独立任务可继续，最终暂停群聊供处理；继续时只重试未完成的失败或停止任务。

通过现有研发任务详情查看工具请求、补充要求、代码变化、验收和合并，详情提供返回群聊入口。群聊任务的首次启动或停止后重启由群聊统一排队；已交付任务可以在预算和并发允许时从详情补充要求。

## 用量和恢复

讨论与研发共用总 token 预算，统计接入 `thread/tokenUsage/updated`，按线程累计而不重复累加通知，并持久化到 SQLite。界面显示总量、并行上限和 80% 提醒。实际计费取决于账户和供应商；功能不将 token 数当成实际账单金额。

达到预算后停止派发任务并请求中断正在执行的工作；事件上报和中断可能有延迟，因此预算不是精确计费上限。运行时未提供用量时显示统计不完整，不能保证预算上限，不能将未知用量解释为免费。

暂停会保留记录和工作树，可调整总预算后继续。客户端或服务退出后，群聊标记中断，必须由用户检查并继续；不在重启后自动重放写入或研发。工作空间备份包含群聊、配置快照和用量；恢复的群聊及研发任务只供查阅，需要在当前项目新建执行。

## 路由

- 群聊列表：`/workspace/:workspaceId/assistant/teams`
- 群聊详情：`/workspace/:workspaceId/assistant/team/:teamId`
- 角色发现：`GET /api/v1/agent-teams/agents`
- 列表与创建：`GET/POST /api/v1/agent-teams`，分页使用 `?page=2`，每页 12 条。
- 详情：`GET /api/v1/agent-teams/:teamId`
- 补充、确认和控制：`POST /api/v1/agent-teams/:teamId/messages|confirm|control`

HTTP API 沿用现有认证、CSRF 和 `X-Workspace-Id` 工作空间隔离；创建和控制操作要求写入权限。资源标识始终使用路径，业务数据使用请求体。
