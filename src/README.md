## Tauri 桌面版（Windows x64 / macOS）

### macOS 开发启动

支持 Apple Silicon 和 Intel Mac。需要 Bun、Rust（通过 rustup 安装）与 Xcode Command Line Tools（`xcode-select --install`）。

```sh
cd src
bun install --frozen-lockfile
# 先停止占用 3210 端口的网页开发服务；沿用项目现有数据
DEDSIWORK_DATA_DIR="$PWD/data" bun run desktop:dev
```

不设置 `DEDSIWORK_DATA_DIR` 时，macOS 桌面数据保存到 Tauri 的应用本地数据目录 `~/Library/Application Support/com.dedsi.work`。开发模式可通过上述变量继续使用 `src/data`。

`bun run desktop:build` 在 macOS 生成 `.app` 和 `.dmg`，在 Windows 生成 NSIS 安装包。服务按当前系统和 CPU 架构编译。macOS 安装包尚未配置签名与公证。

桌面前端和服务资源内嵌在 sidecar 中，不支持网页热更新；修改 `web/`、`server/` 或 `shared/` 后，应退出客户端和开发命令，再运行上述桌面启动命令。仅修改 Rust 桌面代码时，Tauri 开发命令会自动重新编译并重启。需要前端热更新时，使用 `bun run dev`。

现有 React + TypeScript、Bun、SQLite、REST API 与 MCP 保留。Rust 只负责原生窗口、单实例管理、启动和关闭服务。Bun 和 React 资源编译进附带的 `dedsiwork-service.exe`，安装成品不要求用户安装 Bun 或 Rust。

### 开发与打包

开发电脑需要 rustup（管理 rustc/cargo）、Visual Studio C++ Build Tools + Windows SDK、WebView2，以及 Bun。当前电脑已安装这些工具；Rust 安装在当前用户标准目录 `%USERPROFILE%\.cargo` 和 `%USERPROFILE%\.rustup`，其他项目可以复用。新开终端后可执行 `rustc --version` 和 `cargo --version`。

```powershell
cd C:\Githubs\DedsiWork\src
bun run desktop:dev
```

```powershell
# 生成 Windows 安装包
bun run desktop:build
# 查看桌面构建环境
bun run desktop:info
```

桌面命令会自动先编译内嵌 React 资源的 Bun 服务，再启动/打包 Tauri。桌面开发启动不依赖单独的 `bun run dev`；修改前端或服务后需重新启动桌面开发命令以重新打包 sidecar。需要网页热更新时仍可单独使用 `bun run dev`。

### GitHub Actions 打包 Windows 与 macOS

桌面版从 `0.0.1` 开始发布。仓库的 `Build Desktop Installers` workflow 在推送 `v*` 标签时自动生成 Windows x64 NSIS 安装包，以及 macOS Apple Silicon、Intel 两种 DMG 安装包，也支持在 GitHub Actions 页面通过 `Run workflow` 手动运行。

提交并推送版本变更与 workflow 后，发布 `0.0.3` 执行：

```sh
git tag v0.0.3
git push origin v0.0.3
```

推送版本标签后，三个平台全部构建成功才会自动发布 GitHub Release。打开 [版本下载页](https://github.com/DedsiTeam/DedsiWork/releases)，选择对应版本，在发布说明中点击系统下载链接，或在 Assets 直接下载安装包：

- `DedsiWork-v0.0.3-Windows-x64.exe`：Windows 64 位。
- `DedsiWork-v0.0.3-macOS-AppleSilicon.dmg`：M 系列芯片 Mac。
- `DedsiWork-v0.0.3-macOS-Intel.dmg`：Intel Mac。

Release 安装包不受 Actions Artifacts 的 7 天保留期限制。重新运行同一标签的 workflow 会更新该版本的安装包和发布说明。

手动运行分支上的 workflow 只打包，不创建 Release。测试下载步骤：登录 GitHub，打开仓库 → Actions → Build Desktop Installers → 点击对应运行记录 → 在页面底部的 Artifacts 下载 ZIP，解压得到安装包：

- `DedsiWork-Windows-x64-v0.0.3`：Windows `.exe` 安装包。
- `DedsiWork-macOS-AppleSilicon-v0.0.3`：M 系列芯片 Mac 的 `.dmg` 安装包。
- `DedsiWork-macOS-Intel-v0.0.3`：Intel Mac 的 `.dmg` 安装包。

产物保留 7 天，过期后可重新手动运行 workflow。打开 DMG 后将 DedsiWork 拖入 Applications。macOS CI 使用 ad-hoc 签名，尚未配置 Apple Developer ID 签名与公证；首次打开可能需要在“系统设置 → 隐私与安全性”允许打开。

后续发布需同步更新 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 与 `src-tauri/Cargo.lock` 中应用包的版本，再推送对应标签（例如 `v0.0.3`）。workflow 会检查标签与应用版本是否一致。

### 运行行为

- 打开应用时启动附带服务；服务就绪后，窗口自动连接网页并建立桌面会话，无需手动输入配对码。
- 默认网页 `http://127.0.0.1:3210`、API `/api/v1`、MCP `/mcp` 同时可用。外部浏览器自动建立本地会话，无需配对码；MCP 仍要求 Bearer Token。
- 桌面自动登录使用短时、一次性的随机启动令牌，不写入日志，不暴露 MCP 令牌。网页没有 shell、文件系统等 Tauri IPC 权限。
- 点击窗口关闭按钮或按 Alt+F4 时，窗口隐藏到系统托盘，网页、API 和 MCP 继续运行，窗口会话保留。点击托盘图标可重新打开窗口。
- 只有选择托盘“退出 DedsiWork”才正常退出应用：Rust 通过专用 stdin 管道通知服务关闭 SQLite，并等待退出；超时后只终止自己启动的子进程。父进程意外退出造成管道断开时，服务也会自行退出。
- 重复打开应用会聚焦已有窗口，不重复启动服务。端口被其他程序占用时显示启动错误，不接管或停止其他进程。
- 系统托盘使用品牌图标：左键打开主窗口，右键可选择“打开主窗口”或“退出 DedsiWork”；退出时会同时关闭本地服务。
- **启动桌面版前先停止原有 `bun run dev`**，避免同时占用 3210 端口。可以通过 `DEDSIWORK_PORT` 指定其他端口。

### 数据和日志

桌面默认数据在 `%LOCALAPPDATA%\DedsiWork`：`dedsiwork.sqlite`、`access.json`、`desktop-service.log`。可用 `DEDSIWORK_DATA_DIR` 覆盖。升级程序不覆盖这些数据。

已有网页开发数据默认在 `src/data`，不会自动搬移。若要先沿用这些数据，可在启动桌面前设置：

```powershell
$env:DEDSIWORK_DATA_DIR = 'C:\Githubs\DedsiWork\src\data'
bun run desktop:dev
```

如需迁移，先关闭所有服务，备份后复制完整数据目录；不要在 SQLite 仍运行时只复制主数据库文件。

React + TypeScript + shadcn/ui + Bun + SQLite 实现的本地工作项管理工具。网页和 MCP Server 使用同一业务层与数据库。

项目根目录为 `C:\Githubs\DedsiWork\src`，以下命令均在此目录执行。已使用 Bun 1.4.2 验证。

## 启动

```powershell
cd C:\Githubs\DedsiWork\src
bun install --frozen-lockfile
bun run dev
```

打开 [本地工作空间](http://127.0.0.1:3210) 即可直接使用，无需输入配对码。首次启动会自动创建 SQLite 数据库和本地凭据文件；浏览器自动建立有效期为 24 小时的会话，服务重启或会话过期后自动重新连接，保留当前页面地址。

开发模式默认数据目录为本项目的 `data`，不会自动填充演示数据。

`access.json` 包含本地配对码、只读 MCP 令牌 `readToken`、读写 MCP 令牌 `writeToken`。文件只保存于本机并已加入忽略规则。不要将它复制进源码或发布文件。

## 日报管理

`/daily-reports` 以卡片展示日报日期、内容摘要、事项与完成数量，支持搜索、月份筛选及分页。点击「新增日报」进入 `/daily-reports/new` 独立填报页，可选择日期补写；首次点击保存才创建记录，保存成功后转到 `/daily-reports/:id` 修改页。点击卡片或「修改」进入同一修改页，保留自动保存、立即保存、未保存离开提醒、历史事项接续、工作项关联、预览、复制及导出。返回列表保留筛选条件；刷新或直接打开详情链接仍可加载对应工作空间中的日报。

周报、月报继续从日报记录汇总，来源日报按钮跳转到独立修改页，返回时恢复原报告类型。

### 日报回收站

日报删除后进入回收站，可恢复或永久删除。打开回收站中的日报，点击「永久删除」并确认后，记录从当前工作空间数据库中物理移除，无法恢复。永久删除接口为 `POST /api/v1/daily-reports/:id/purge`，请求体为 `{expectedVersion, confirmed: true}`；仅允许删除回收站中的当前版本，沿用写权限及 CSRF 校验。

## 领域模型管理

模型列表每行操作栏的树形图标可打开“领域模型一张图”（`/domain-models/:id/diagram`）。树图从左到右展示模型、类型和设计项，五类类型依次为聚合根、实体、值对象、领域事件、领域事件处理器；处理器按对应事件顺序排列，并标明一对一关联。支持分支折叠、单项或全部字段展开、缩放、适应宽度以及拖动画布空白处。图中内容读取已保存的模型，编辑保存后可在图页刷新。

领域事件与领域事件处理器在同一模型内一对一关联。处理器通过 `eventId` 选择对应事件；保存时要求每个事件恰好对应一个处理器，不允许重复绑定、未绑定或跨模型绑定。移除事件时保留处理器内容并清空关联，重新关联或移除该处理器后才能保存。历史未建立关联的模型需要在下次保存前补齐。

左侧“领域模型 → 模型管理”提供模型的新建、查询、编辑和删除。一个模型包含聚合根、实体、值对象、领域事件和领域事件处理器五类设计项，每类可添加多个。设计项包含名称、说明与字段列表；每个字段维护名称、数据类型和说明，类型可以从常用类型中选择，也可以输入自定义类型。

模型列表地址为 `/domain-models`，新建为 `/domain-models/new`，编辑为 `/domain-models/:id`。新增和移除设计项、字段均在点击“保存模型”后生效；离开未保存页面时会提示。列表支持按模型名称和说明搜索、分页及删除确认。

模型编辑采用左侧设计项目录、右侧编辑区，一次编辑一个设计项，保存时校验完整模型并定位存在问题的设计项。已保存模型可通过顶部“设计 / 一张图”切换视图，目录选择、树图缩放和分支折叠状态会在本机记住。保存状态显示在顶部，仍使用手动保存。

数据保存在原有 SQLite 数据库的 `domain_models` 表，通过版本 2 的增量迁移创建。保存和删除使用版本号保护，过期版本不会覆盖较新修改；删除为逻辑删除，模型从列表中移除。该模块不包含限界上下文、模型关系、业务规则或代码生成，也未新增 MCP 工具。

REST 接口：`GET/POST /api/v1/domain-models`，`GET/PUT/DELETE /api/v1/domain-models/:id`。PUT 接收 `{ expectedVersion, model: { name, description, elements } }`，DELETE 通过 `If-Match` 提交版本号。接口沿用本地身份验证、写权限及浏览器 CSRF 校验。

## MCP 接入

连接类型为 **Streamable HTTP**，地址为 `http://127.0.0.1:3210/mcp`。客户端需要发送：

```http
Authorization: Bearer <access.json 中的 writeToken 或 readToken>
```

网页“服务与 MCP”页面提供连接参数示意。各 MCP 客户端配置文件的字段不同，请将 URL 和请求头填入相应位置。服务只监听本机回环地址，远端云客户端不能直接访问此地址。

| 工具                | 用途                             |
| ------------------- | -------------------------------- |
| `work_item_list`    | 搜索、筛选、分页和回收站查询     |
| `work_item_get`     | 读取详情与版本                   |
| `work_item_create`  | 创建，可携带 requestKey          |
| `work_item_update`  | 修改，必须携带 expectedVersion   |
| `work_item_delete`  | 软删除，必须携带 expectedVersion |
| `work_item_restore` | 恢复，必须携带 expectedVersion   |
| `work_item_events`  | 分页读取活动记录                 |

例如，客户端可以调用：

```json
{
  "name": "work_item_create",
  "arguments": {
    "title": "完善项目说明",
    "description": "补充启动流程与 MCP 接入方法",
    "priority": "normal",
    "requestKey": "unique-request-key"
  }
}
```

更新前调用 `work_item_get`，读取当前 `version`，随后将它作为 `expectedVersion` 提交。遇到 `VERSION_CONFLICT` 后重新读取并决定如何合并，不能直接覆盖。只读凭据调用写工具会被业务层拒绝。

项目附带真实 SDK 客户端示例。服务启动后，可在另一个终端执行：

```powershell
bun run mcp:check
```

示例默认读取开发数据目录中的 `readToken`，只列出工具和前 5 个工作项。若数据目录或端口不同，请在两个终端中设置相同的 `DEDSIWORK_DATA_DIR`、`DEDSIWORK_PORT`。

## 构建与正式运行

```powershell
bun run build
bun run start
```

构建输出前端静态文件至 `dist`，正式服务提供这些文件并运行 TypeScript 后端。正式模式默认数据目录为 `%LOCALAPPDATA%\DedsiWork`，与开发数据分开。若希望两个模式访问同一数据库，显式设置相同的数据目录：

```powershell
$env:DEDSIWORK_DATA_DIR = 'C:\Githubs\DedsiWork\src\data'
```

同一端口同时只能启动一个服务。源码修改使用 `bun run dev`；正式模式修改前端后需要重新构建。按 Ctrl+C 关闭服务，浏览器窗口关闭不会停止服务。

## 数据备份与当前边界

先停止服务，复制完整数据目录到备份位置。恢复时先停止服务并保留当前目录副本，再替换数据目录并重新启动。备份包括凭据文件，恢复数据库时可选择保留现有凭据；凭据变化后需要更新客户端配置。

第一版面向单用户本机使用，创建和修改使用同一个独立编辑页面，移入回收站前需要二次确认。描述支持富文本、格式工具及本地图片选择、粘贴和拖入。暂不包含自动执行器、在线备份、多用户或远程访问。MCP 提供工作项管理能力，创建工作项不会自动运行 AI 任务。


### 富文本描述

网页编辑使用 Tiptap。新富文本描述在原有 `description` 字符串中以 `<!--dedsiwork-richtext-v1-->` 开头，后面是 HTML；没有此前缀的历史描述按纯文本显示，不会自动解释 HTML。无需数据库迁移。MCP 读取和更新继续使用同一字段，修改其他字段时应省略 description，避免覆盖已有图文。

图片以 Base64 嵌入描述并随工作项及历史记录保存在 SQLite 中，不上传外部服务。支持 PNG/JPEG/GIF/WebP，选择、粘贴和拖入的单张文件最多 1 MiB；描述整体最多 2,000,000 字符（含图片编码和 HTML）。HTTP/MCP 请求上限 8 MiB。网页展示前清洗 HTML，只保留支持的格式和内嵌位图图片，外部图片不加载。

图片会增加数据库及活动记录体积，备份时仍需备份完整数据目录。旧 Markdown 源文本保持原样显示，暂不自动转换格式。


### 回收站永久删除

回收站列表支持每行永久删除、勾选批量永久删除、全选当前页。切换页面或筛选条件会清空勾选；后台刷新时，已变更版本的勾选会取消。确认弹窗列出目标并提示不可恢复，取消不会发送删除请求。

`POST /api/v1/trash/purge` 接收 `{ "items": [{ "id": "工作项 UUID", "expectedVersion": 2 }] }`，单项与批量使用同一接口，每次 1–100 项且不能重复。遵循原有写权限与浏览器 CSRF 校验。仅能删除仍在回收站且版本匹配的项目；任一项失败时整批回滚。

永久删除会移除工作项（包括图文描述）及关联活动记录，创建请求缓存只保留删除标记，旧幂等键重试返回 410，避免重新创建或返回已删除内容。不涉及磁盘安全擦除或既有备份文件清理。现有 MCP 的 `work_item_delete` 仍为移入回收站。

### Web 页面与路由

使用 React Router 的 `createBrowserRouter` 和嵌套 `Outlet`。`web/App.tsx` 负责本地自动连接、公共布局和工作空间统计，具体业务页面位于 `web/pages/`。

| 页面 | 地址 |
| --- | --- |
| 全部工作项 | `/work-items` |
| 进行中 | `/work-items/in-progress` |
| 已完成 | `/work-items/completed` |
| 回收站 | `/work-items/trash` |
| 创建工作项 | `/work-items/new` |
| 查看与修改工作项 | `/work-items/:id` |

根地址自动跳转到全部工作项。页面支持直接打开、刷新和浏览器前进后退；编辑页根据地址中的 ID 从服务读取数据，自动连接后仍保留原目标地址。未保存时，通过菜单、返回按钮或浏览器后退离开会出现确认框；刷新、关闭页面仍使用浏览器的未保存提醒。

左侧菜单按功能模块分组，可折叠。新增功能时，在 `web/pages/` 添加页面，在 `web/router.tsx` 注册带 `handle.title` 的路由，再在 `web/navigation.ts` 添加菜单分组或子项；公共布局不必改动。菜单使用 `NavLink`，支持高亮和在新标签页打开。遵循根目录 `AGENTS.md` 的 UI 配色规范，复用语义化主题变量。

开发服务使用 Bun HTML 路由回退，生产服务对页面导航返回构建后的入口 HTML；`api`、`auth`、`mcp`、`healthz` 保留服务端处理。入口使用根路径 base，确保深层页面刷新后的资源加载正确。部署到其他服务器时也需要配置对应的 SPA 回退。

本次验证：18 项既有测试通过；开发和生产模式各验证 8 个页面地址及 API/认证/健康检查边界；浏览器验证了配对保留目标地址、新建后跳转编辑地址、刷新编辑页、返回列表、菜单折叠、未保存时取消导航与后退保护。


## 冲刺看板

左侧「工作项 → 冲刺看板」（`/work-items/sprints`）提供第一版冲刺闭环。默认选择进行中的冲刺；可以切换计划中和已结束的冲刺，所选冲刺保存在 URL 查询参数 `sprint` 中。

- 创建冲刺时填写名称、目标和起止日期；同一时间最多一个进行中的冲刺。
- 从已有工作项批量加入，候选列表支持搜索和分页。每个工作项最多归属一个未结束的冲刺；移出后保留原状态和截止日期。
- 看板按待处理、进行中、待评审、待验证、待验收、已暂停、已完成分列，已取消默认收起。阻塞作为独立标记保留所在阶段，可填写原因或解除。支持搜索、类型与优先级筛选、点击统计筛选、拖动改状态和列内排序，也可通过卡片菜单修改状态。拖到另一卡片上方表示插入该卡片之前，拖到列空白处表示追加。
- 每列可直接新建工作项。点击卡片在右侧抽屉编辑完整信息，沿用富文本、活动记录、未保存提醒与版本冲突保护；卡片保留复制给 Codex 操作。
- 开始后可结束冲刺，未完成项可以退回待规划区，或结转到已有的计划中冲刺。结束、结果快照和结转在同一数据库事务中完成。
- 已结束冲刺只读，保存结束时的卡片内容、顺序和状态。此后工作项修改、移入回收站或永久删除不会改变历史冲刺快照；快照仍保留结束时内容。
- 看板每 5 秒刷新，窗口重新获得焦点时也刷新。写操作校验冲刺版本；状态更新另校验工作项版本。冲突时保留编辑输入，刷新后重新操作。

数据库版本 3 增量增加 `sprints`、`sprint_items`、`sprint_snapshots` 和 `sprint_events` 表，已有工作项保持原样。冲刺活动记录包含网页/MCP 来源。

REST 接口：`GET/POST /api/v1/sprints`；`GET/PUT /api/v1/sprints/:id`；`POST /api/v1/sprints/:id/{start,finish,add,remove,move,create-item}`。GET 详情返回 `{ data: { sprint, items, events } }`，PUT 接收 `{ expectedVersion, sprint: { name, goal, startDate, endDate } }`。写接口沿用本地认证、写权限与 CSRF 校验。

新增 MCP 工具：

| 工具 | 用途 |
| --- | --- |
| `sprint_list` | 列出冲刺 |
| `sprint_get` | 查询看板、最新版本和最近活动 |
| `sprint_create` | 创建计划中的冲刺，接收 `{ sprint: { name, goal, startDate, endDate } }` |
| `sprint_update` | 修改冲刺信息 |
| `sprint_start` | 开始冲刺 |
| `sprint_add_items` | 批量加入工作项 |
| `sprint_remove_items` | 批量移出工作项 |
| `sprint_move_item` | 修改卡片状态和顺序 |
| `sprint_create_item` | 在指定列创建工作项 |
| `sprint_finish` | 结束并退回或结转未完成项 |

除创建外，写工具接收 `id` 和冲刺最新 `expectedVersion`。加入/移出接收 `items: [{ id, expectedVersion }]`（每次最多 100 项）。移动接收 `itemId`、`itemVersion`、`status` 与可选 `beforeId`；已完成或取消的工作项需先移动到 `todo` 重新打开。冲刺内创建接收 `item`（普通创建字段，初始状态为 `todo`）、目标列 `status`、`requestKey`。结束时 `targetSprintId: null` 表示退回待规划区；结转需传目标计划中冲刺 ID 和其最新 `targetVersion`。`work_item_list` 新增 `unplanned: "true"` 用于查询可加入的工作项。

验证包含冲刺生命周期、单活跃冲刺约束、归属与排序、版本冲突、只读权限、失败事务回滚、历史快照，以及实际 MCP 客户端和网页 API 的跨入口联动。

### AI 创建领域模型（桌面客户端）

在「领域模型」列表点击「AI 创建」，输入业务需求，生成草稿后使用现有模型编辑器预览和修改，点击「保存模型」才写入数据库。生成结果包含聚合根、实体、值对象、领域事件、领域事件处理器，以及字段的数据类型和说明；事件和处理器按一对一校验。支持取消、失败重试、离开页面后恢复当前任务。任务在后台内存中最多保留 20 个，30 分钟后过期，客户端退出后不保留生成任务，已保存模型不受影响。

客户端启动时自动启动私有 `codex app-server --listen stdio://` 子进程，退出时一起清理；无需打开 Codex 桌面窗口。使用当前用户的 Codex 登录，未登录时可在 AI 页面点击「登录 Codex」，通过系统浏览器完成认证。CLI 优先使用 `~/.local/bin/codex`，也支持 PATH 中的安装；可通过 `DEDSIWORK_CODEX_PATH` 指定 CLI 完整路径。需要先安装官方 Codex CLI（本次接入使用 0.162.1）。

AI 以临时目录和只读沙箱运行，关闭 shell、应用、浏览器等工具，使用结构化输出，生成时不会自动保存或执行模型中的业务操作。接口位于 `/api/v1/domain-models/ai/`：`GET status`、`POST login`、`POST generate`、`GET jobs/:id`、`POST jobs/:id/cancel`，沿用本地认证、写权限和浏览器 CSRF 检查。一次只能运行一个生成任务，超时为 8 分钟。

### 交付阶段、暂停与阻塞

工作项和 MCP 统一支持 `todo`（待处理）、`in_progress`（进行中）、`in_review`（待评审）、`in_verification`（待验证）、`awaiting_acceptance`（待验收）、`paused`（已暂停）、`done`（已完成）、`cancelled`（已取消）。允许跳过不适用的阶段；已完成或取消仍需先重新打开为待处理。已暂停和待评审/验证/验收均属于未完成，冲刺结束时可结转。

`blockedReason` 非空表示阻塞，保留当前阶段；清空表示解除，最多 1000 字。网页卡片和详情均可操作，MCP 使用 `work_item_update` 更新，列表可用 `blocked: "true"` 筛选。完成或取消时自动解除阻塞，并在活动记录中保留变更。

从待评审、待验证、待验收退回进行中时，网页提示填写原因，MCP `work_item_update` 必须提供 `transitionReason`，`sprint_move_item` 必须提供 `reason`，原因计入工作项活动记录。暂停后的恢复不要求退回原因。

数据库迁移版本 4 扩展工作项状态并增加阻塞原因，保留工作项、冲刺归属、活动记录与幂等记录。旧 `blocked` 状态转换为进行中并标记「历史阻塞工作项（原阶段未记录）」；历史冲刺快照原始数据保留，读取时以同样规则兼容显示。

看板列保持可读宽度，较窄窗口横向滚动。拖动采用指针捕获，支持从卡片标题或空白区域拖动，目标列高亮；拖动时按 Escape 可取消，卡片操作栏保持独立点击。


### 空冲刺删除与概览折叠

没有工作项的冲刺显示「删除冲刺」，适用于计划中、进行中和已结束冲刺。删除需要二次确认；服务在同一事务中再次校验版本及完整冲刺内容，不受当前看板筛选影响。有非空历史快照的冲刺不可删除。回收站工作项不计入当前看板，删除空冲刺只解除这类关联，不删除工作项或其活动记录；恢复后可重新安排。删除冲刺及其自身活动、空快照后无法从界面恢复。

`DELETE /api/v1/sprints/:id` 接收 `{ expectedVersion, confirmed: true }`。新增 MCP `sprint_delete` 使用同样参数并额外接收 `id`，只读凭据不能删除，未确认请求会被拒绝。

页面右上「新建冲刺」左侧的箭头可展开/折叠冲刺选择、目标、统计与管理操作区域；筛选栏和看板保持显示。折叠偏好保存在本机，刷新后保留。删除后自动切换剩余冲刺；全部删空时回到创建引导。

### ChatGPT / 本地 Codex 对话

左侧顶部新增「ChatGPT」入口（`/chat`）。对话通过独立的本地 Codex App Server 进行，沿用本机 CLI 登录、Skills、MCP、插件和工具配置，不使用领域模型生成器的只读工具限制。支持连续对话、历史恢复与分页加载、Markdown/代码/表格、图片输入（每次最多 2 张，每张 2 MB）、查看命令和文件修改等工具过程，以及停止当前回复。新对话可指定模型；工作目录统一使用工作空间的本地工作目录，未配置时使用该空间数据目录下的 `chat-workspace`。AI 对话不再单独设置目录，研发任务自动读取同一目录的 Git 仓库与分支，无需再次选择文件夹。

工作目录采用 `workspace-write` 沙箱和 `on-request` 授权策略，授权由用户处理。命令、文件和额外访问权限请求在对话中显示确认卡片；补充信息请求显示问题与选项；MCP 表单可查看请求 schema 并填写 JSON，URL 授权可打开系统浏览器。权限仅对本次任务授予，前端不会自动批准请求。工具是否可用仍取决于本机 Codex 配置、账号权限和相关工具服务。

页面右上角「打开 ChatGPT」通过系统启动本机 ChatGPT 应用。macOS 查找 `/Applications/ChatGPT.app` 或 `~/Applications/ChatGPT.app`；未安装时在界面显示提示。该按钮独立于内嵌 Codex 对话，不会自动把消息发送到外部应用。

接口位于 `/api/v1/chat/`，沿用本地认证、写权限及 CSRF 校验。`GET status`、`POST login`、`GET/POST threads`、`GET threads/:id`（`older=true` 加载历史，`since` 用于增量刷新）、`POST threads/:id/messages`、`POST threads/:id/stop`、`POST threads/:id/requests/:requestId`，以及 `POST open-app`、`POST open-link`。对话发送带客户端消息 ID，避免重复提交。

### 单一对话式 AI 助手

AI 助手现仅保留自由对话，移除「需求到模型」模式及切换按钮。根据对话内容，Codex 可提出工作项或领域模型草稿，回复中的结构化草稿显示为预览卡片。用户点击卡片后可编辑、勾选并确认保存；服务端从当前身份的原始助手回复读取并校验草稿，不信任浏览器上传的生成内容。相同回复的预览使用稳定 ID，重复保存不会创建重复记录。普通对话不会自动生成业务记录。

领域模型可直接根据对话建模，保持单聚合根、事件与处理器一对一、字段类型与说明的约束。保存后回到同一对话，后续消息会带入已确认创建的结果。已有流程草稿及来源记录保留。`POST /api/v1/chat/threads/:id/proposals` 接收 `{messageId,index}`，返回供预览确认的草稿；创建仍使用助手的确认接口。

对话历史行右侧提供删除图标，确认后调用 `DELETE /api/v1/chat/threads/:id`（`{confirmed:true}`）。服务仅处理当前身份的对话，先归档对应 Codex thread，再删除本应用对话索引并释放缓存；已创建工作项、模型及来源记录保留。正在回复的对话需先停止。Codex 明确返回当前对话的历史文件不存在（`no rollout found for thread id`）时，继续删除本应用索引并释放缓存；其他归档、连接及权限错误仍保留记录并提示。删除当前对话后回到新对话。

### 工作空间管理

软件启动进入「工作空间」管理页。每个工作空间独立拥有 AI 对话、工作项与回收站、冲刺、领域模型、活动和 AI 草稿。卡片支持搜索、打开、编辑和删除，按最近打开排序；名称必填，说明与本地工作目录可选，macOS 与 Windows 均可调用系统文件夹选择器（Windows 使用系统自带的 Windows PowerShell）。新建、编辑及恢复工作空间共用目录选择器，支持中文和带空格的路径，取消选择保留原目录，也可手动填写完整路径。打开后默认进入 AI 助手，侧栏顶部可切换、编辑或返回管理页。

首次升级自动创建「默认工作空间」，完整沿用原 `dedsiwork.sqlite`，无需复制或重建原业务记录。工作空间目录登记于 `workspaces.sqlite`；新增空间使用 `data/workspaces/<id>/dedsiwork.sqlite`，业务 schema 继续使用原有迁移。已删除空间不会在下次启动时重新创建。Codex 登录凭据为全局，工作目录、背景说明、历史索引和 UI 对话选择按空间独立。

工作空间 CRUD 接口位于 `/api/v1/workspaces`，编辑传 `expectedVersion`，删除须传 `{confirmed:true,name,expectedVersion}`。删除前关闭该空间拥有的服务并删除本应用数据库，不触碰用户指定的本地工作目录，也不删除 Codex 全局历史文件。现有 REST 接口通过 `X-Workspace-Id` 选择空间；MCP 配置页提供 `/mcp?workspace=<id>` 的空间专属地址。未带空间参数的旧 API/MCP 请求仅兼容指向默认工作空间；默认空间删除后要求显式选择，避免转向其他空间。外部工作项链接携带 `workspace` 参数。

按用户要求，仅编译并重启客户端，未运行测试、UI 自动化或实际 AI 生成。

顶部栏右侧显示当前工作空间名称与返回列表图标，不提供空间间直接切换。用户须返回管理页选择其他工作空间；退出时先完成路由离开确认，再清空空间上下文。Codex 空间信息回调使用独立字段 `workspaceInfo`，避免覆盖启动器内部临时工作目录。

### 单工作空间备份与恢复

管理页卡片菜单提供「备份工作空间」，通过原生保存窗口生成 `.dwb` 文件；页面右上提供「恢复工作空间」。恢复先展示备份时间、工作项（含回收站）、冲刺、模型和对话数量，可设置新名称与本地目录，确认后创建独立的新空间。原空间和用户本地代码目录不会被覆盖。

备份采用 SQLite `VACUUM INTO` 一致性快照，包含活动、幂等记录、来源关联与 AI 草稿。文件为带格式版本、SHA-256 校验和数据库内容的 gzip 包，不含登录凭据和用户代码目录。恢复先校验大小、版本、哈希、数据库完整性及关联，再将白名单业务表通过参数化写入全新数据库，不执行备份文件的建表 SQL。失败清理新数据库并回滚目录登记；同一恢复预览的重复提交不会创建重复空间。

数据库迁移 8 增加实际对话消息快照。备份读取全部历史分页；正在回复的对话要求先停止，无法获取完整历史时提示重试。恢复的对话可离线阅读；首次续聊建立独立 Codex thread，带入近期上下文，重启后继续保留恢复历史。上下文最多约 8 万字符，更早消息仍保留在应用历史里。未完成的 AI 生成任务恢复为可重试状态，原 Codex 会话不受影响。

新增 POST `/api/v1/workspaces/:id/backup`、`restore-preview`、`restore`、`restore-discard`，沿用认证、写权限与 CSRF 校验。恢复预览临时文件 20 分钟过期，取消或退出时清理。按用户要求未运行自动化测试、UI 测试或实际 AI 对话测试。

## 无边记

进入工作空间后，从左侧「无边记」打开管理页，支持搜索、新建、编辑和删除；删除笔记或画布元素均需确认。

画布使用 LeaferJS，可添加文字、图片、矩形、椭圆与三角形。选中元素后可拖动、缩放、旋转，右侧可修改文字、字号、加粗、颜色、尺寸及层级。按住空格拖动平移，滚轮缩放，右下角可适应全部内容。图片可通过工具栏选择或拖入画布（GIF 保存为静态图片）。

点击「保存」将内容保存到当前工作空间；未保存离开时会提醒。「导出图片」会将全部内容（含视口外元素）导出为白底 PNG，使用本地保存窗口选择位置。每张画布最多 200 个元素、约 6 MB 内容；图片自动压缩，导出最长边 8192 像素、总像素最多 1600 万。

工作空间 `.dwb` 备份包含无边记与内嵌图片；仍支持恢复加入无边记之前的备份。

无边记支持字体选择（默认、苹方、微软雅黑、宋体、楷体、Arial、Georgia、等宽），缺失字体时使用系统回退字体。图形内可直接输入文字并调整字体、字号与文字颜色；双击图形可编辑其中的文字。新增正圆、正三角形，缩放保持比例。

拖动空白处框选，或按 Shift 点选多个元素，右侧显示六种对齐、水平/垂直等间距分布（至少 3 个元素），以及自定义边缘间距（至少 2 个元素）。等间距分布保留两端位置，自定义间距从左侧或顶部元素开始排列。多选删除同样需要二次确认。

无边记连线：点击左侧「连线」后，依次点击画布起点和终点（Esc 取消）。选中连线后可拖动两端的圆点改变端点，或用方向键微调（Shift 为 10px）。支持直线、曲线、折线、圆角折线，0.5–20px 粗细、颜色、实线/圆点线/虚线，以及两端独立设置无箭头、开放箭头、实心箭头、圆点、菱形。连线随画布保存、导出图片和工作空间备份。

连线端点支持吸附到矩形、圆/椭圆、三角形边缘；点击形状内部会连接最近边缘。吸附点以形状上的相对位置保存，移动、缩放和旋转形状时连线端点同步更新。拖动端点离开形状可解除吸附，也可在属性面板解除。曲线/折线/圆角折线选中后显示菱形调整手柄，拖动可调整弯曲或中间线段；面板可重置拐点。连线类型、样式、两端箭头改为图标单选，支持方向键切换，选中项显示紫色高亮边框。

## 研发任务

工作空间内从左侧「模型管理」下方的「研发任务」进入。创建时自动使用工作空间本地工作目录中的 Git 仓库，无需再次选择目录；显示当前分支、选择执行模型，关联最多 20 个工作项和 10 个领域模型，或填写研发要求。新任务只保存关联 ID、名称和关联时版本；开始或继续研发时读取最新资料，生成本次执行专用的本地资料索引，由执行助手按需分段读取，不再限制关联资料的总字符数。领域模型按设计元素拆分文件，避免整包内容挤占首条消息。资料已删除时明确提示恢复后重试；历史任务仍使用创建时快照。研发要求仍最多 16,000 字符。

创建后自动开始研发，直接在工作空间本地工作目录和当前分支执行，不创建 Git 工作树或研发分支，不切换分支。保留并使用目录已有的未提交修改；同一工作空间一次只能执行一个研发任务。工作空间目录或分支变化后，须恢复原配置或创建新任务。

任务详情的「执行进度」通过 SSE 连接接收任务更新，后台每 500ms 收集 Codex 事件变化，展示执行计划、回复、命令输出、文件修改及授权/补充信息请求。切换页面仍会继续执行，返回后恢复已有记录；连接中断自动重连。停止后可以补充要求继续同一会话。客户端或后台退出后，未完成任务标记为中断，由用户明确选择继续。

「代码差异」读取相对任务基准提交的跟踪文件差异、未跟踪文件列表和最近提交。新文件的完整内容通过研发目录查看。默认不运行测试，由用户测试与验收；不自动提交、推送或合并。Codex 执行结束进入「待验收」，用户确认完成后保留分支和代码，关联工作项的状态不自动改变。

人工接管先停止执行，再点击「打开 ChatGPT 接管」，自行提供任务信息并使用工作空间本地工作目录；此入口仅打开应用，不保证自动接续同一 Codex 会话。用户也可以直接打开研发目录自行修改，然后回到任务继续。

业务数据使用数据库迁移 12 的 `development_tasks` 表，研发会话与普通 AI 助手入口隔离。工作空间备份包含任务记录、需求快照和已有执行记录，不包含代码仓库、工作树或依赖。备份前需要停止执行中的任务。恢复后的研发任务仅供查阅，不会自动使用备份中的本地路径执行代码，继续研发需要在工作空间配置本地工作目录并创建新任务。

直接执行的任务无需合并，不提供合并或清理目录操作。历史独立工作树任务保留查阅与合并能力，不再继续在旧工作树执行，也不自动迁移或删除其中的代码；后续研发请创建新任务。代码差异包含目录已有修改，不能视为当前任务独占的改动。

已通过隔离测试仓库验证授权接受/拒绝、异常重启续接、备份恢复及合并。授权事件使用可控 AppServer 测试进程注入，实际界面和业务服务参与验证。

AI 助手默认按完整业务功能生成工作项。例如教师管理只生成一个工作项，其说明统一包含前端、后端、数据库、测试和验收，并由一个研发任务整体交付。只有用户明确要求拆分或包含多个独立业务功能时才生成多个工作项。自由对话和结构化需求草稿使用相同规则。


创建研发任务后会立即启动 Codex，在工作空间本地目录中持续实施并实时展示执行记录，交付后进入「待验收」。需要额外授权或必要信息时暂停等待用户，不会自动批准请求。验收完成始终由用户手动确认，代码提交由用户自行处理。

顶部铃铛「研发提醒」汇总所有工作空间中当前用户的待验收、等待处理、失败和中断任务，提醒持久保存；「知道了」只关闭提醒，不会验收或合并。可在此开启系统桌面通知，macOS 和 Windows 使用 Tauri 原生通知插件；未允许通知时仍保留应用内提醒。Windows 系统通知应使用安装后的客户端验证。关闭窗口保留后台运行，完全退出客户端会停止服务，重启后可继续中断任务。

### 领域模型与研发任务 MCP

领域模型提供 `domain_model_list/get/create/update/delete`，复用页面的模型结构校验和版本冲突检查。创建传 `{model}`，更新传 `{id,expectedVersion,model}`。

研发任务提供 `development_task_list/get/repository/create/start/stop/message/answer/complete/changes/notifications/acknowledge/merge_preview/merge/cleanup/open_directory/handoff/status/login`。先调用 `development_task_repository` 自动读取工作空间目录，再以 `{task:{title,requirement,directoryToken:token,baseBranch:currentBranch,itemIds,modelIds,model}}` 创建并立即执行。所有路径都来自工作空间设置，不弹出选择器。通过 get 轮询执行进度和待处理请求；验收 complete 须传 confirmed:true，权限审批 answer 应传达用户的明确决定，不能自动批准。

MCP 研发任务沿用现有调用身份隔离：writeToken 对应 mcp-write，readToken 对应 mcp-read，网页对应 local-user，各身份不能读取或操作其他身份的研发任务。领域模型和工作项按工作空间共享。若需读取 MCP 创建的研发任务，须继续使用原写入凭据；只读凭据仍不能执行写操作。现有页面中的研发任务不会因此自动暴露给外部 MCP 调用者。

新研发任务直接使用工作空间目录，不支持合并或清理。历史任务的合并、清理沿用既有保护，merge/cleanup 须传 confirmed:true；merge token 来自预览。所有工具复用现有服务，异步调用完成后返回结构化结果，失败返回 MCP 错误。创建模型及研发任务尚无通用幂等键，响应不确定时先查询确认，不应直接重复创建。

### 网址导航

侧栏 AI 助手下方新增「网址导航」。每个工作空间独立保存分组、网址、说明和排列顺序；支持新建、编辑、删除确认，以及编辑模式下调整分组和网址顺序。页面采用分组标题和横向平铺网址卡片，点击网址通过系统浏览器打开。卡片采用紧凑文字布局，不显示或请求网站图标。仅接受不含账号密码的 HTTP/HTTPS 地址。

数据保存到工作空间数据库的 bookmarks 表，使用版本号防止覆盖其他页面的修改；已接入工作空间备份恢复，旧版备份恢复时导航为空。无需安装浏览器扩展或单独启动服务；没有读取或修改 NewTabDashboard 项目。接口为 GET/PUT /api/v1/bookmarks，沿用现有空间隔离、读写权限和 CSRF 校验。

### 冲刺与日常执行联动

- 新建工作项可以选择计划中或进行中的冲刺，创建与加入在同一事务中完成；重复请求不会创建重复工作项。已有工作项可在列表多选后批量加入，详情显示所属未结束冲刺及跳转入口。
- 看板卡片可发起研发任务，自动带入工作项与标题；卡片每 5 秒刷新关联研发任务状态。已结束冲刺继续保持历史快照，不显示实时研发信息。
- 看板默认展示待处理、进行中、待验收和已完成；其他阶段有工作项时自动显示，也可手动展开全部阶段。
- 研发进入待验收或完成后，可以在“关联工作项验收”选择工作项，提交待验收或标记完成。更新校验任务所有者、关联关系和工作项版本，并以事务提交；不会自动把研发完成等同于工作项完成。
- 日报的工作项选择器默认显示当前进行中的冲刺，可切换到全部工作项。看板提供可编辑、可复制的迭代回顾草稿，按完整看板汇总完成、未完成与取消项；草稿不会自动保存。

新增查询 `GET /api/v1/work-items/:id/sprint` 返回当前未结束冲刺或 null。`POST /api/v1/development-tasks/:id/update-items` 接收 `{ status: "awaiting_acceptance" | "done", items: [{ id, expectedVersion }] }`。冲刺内创建接口额外返回 `data.createdItem`，支持相同请求标识重试。

Ai Agent 支持在现有对话中根据需求工作项与领域模型生成 `development_items` 研发任务草稿。助手读取当前工作空间的本地资料索引，按业务功能组织任务；草稿卡片可预览、编辑和勾选，用户确认后才保存为 `task` 工作项。来源 ID 和版本会校验，资料变更时需重新生成，重复确认不会重复创建。确认结果提供“创建研发任务”，自动带入该研发任务和关联领域模型，再由用户确认启动研发。
